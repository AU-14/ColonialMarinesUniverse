Lobby Housing Sketch
CMU · lobby · housing sketch, second pass

The lobby as the same terminal

The in-round chat already sits in a molded housing on a CRT screen. This tries the same language on the lobby's right column - server info, character, chat - as one piece of equipment instead of three flat CRT panels stacked on top of each other. The server info block is corrected to what a server actually sends by default: six round-info lines in a GOVFOR/OPFOR pair table, plus players and round time on their own line above it - not the four loose rows the first pass showed. That extra height is also why this pass adds a second idea: switching between server info and character instead of always stacking both. Nothing here is built; the shipped scope today is chat only, shown for comparison.

Read this as "would the pieces fit," not "is it built." Every texture and style rule this needs already exists from the chat and top-bar work; this is about whether stitching them across the lobby's other two blocks is worth doing.
The switch is its own idea, independent of housing. It's worth trying flat too - "Top panel: Switchable" works with housing Off, since a taller info block is a real problem for today's shipped look as well, not only for a housed one.
Off keeps the flat panel, the same as the in-round chat: the housing is opt-in via cmu.chat_housing, and this sketch assumes the lobby would follow the same cvar.
One screen, not two. The first pass gave info/character and chat their own glass each, with plastic between them - two thin rings sitting close together, not a deliberate line. This pass merges them into one screen.
The switch is a toggle, not a tab, once it's housed. The tab pair (an underline drawn on the glass) is still what you get with the flat panel and the chat-only housing scope, since the switcher there is genuinely part of the display. Once the whole panel is housed, "Server" and "Character" become a two-position detent switch on the plastic between the command keys and the screen - a recessed track with one paddle that snaps to whichever side is active, rather than two separate keycaps sat next to each other. A pair of flat buttons still reads as a segmented control no matter how they're shaded; a single sliding paddle with a centre notch reads as a physical switch, which is closer to what would actually sit on a terminal like this one rather than something borrowed from a phone UI.
The seam is now a strip of casing, not a glowing rule. The rule (Surface4, the in-round top bar's own "heavy rule") reads as a UI element - a tab underline, essentially - which says "these are two sections of one screen," not "these are two screens." The case-seam tile is unlit, textured like the housing's own plastic, and carries a rivet every 64px, the same bevel and screw language as the housing's corners. Everything either side of it is an active display; the one strip that plainly is not a display is what actually tells you it is a seam, generated once as a small tileable PNG (make_seam.py, alongside the existing make_housing.py) rather than drawn as a CSS rule.
What this can't show: the in-game scanline grain, and a server whose operator has written a longer intro blurb than the fixed one line the default sends - ServerInfo.SetInfoBlob can render several more lines of that below the grid, which either view here would need room for.
