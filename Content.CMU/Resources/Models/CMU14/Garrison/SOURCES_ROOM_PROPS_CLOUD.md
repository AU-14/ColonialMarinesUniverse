# Room furniture and small props: physical draft study

Asset-only work against TheHellFireo/CMU-Garrison-3D, ref `Chip/garrison-3d`, inspected 2026-10-06. All 25 assemblies remain `draft`. The 15 exact source IDs account for 34 Redux / 14 classic entries in the supplied historical inventory. These are inventory totals, not verified visible placements, supported live states or map-fit coverage.

Canonical definitions: `garrison_room_props_cloud.yml` and `garrison_room_props_cloud_art.yml`. Original crop textures are under `Textures/CMU14/ThreeD/room_props_cloud/`, reserved atlas range 3114–3199. Only 3114–3136 are currently used. Authoring is reproducible via `Tools/three_d/author_room_props_cloud.py`; it uses the unchanged `build_models` validator, rasterizer and GLB exporter. Proof, exact crop ledger, source metadata and three-view comparisons are in `Tools/three_d/generated/cloud-review/room-props/`. The source input manifest is `reference/room-props-fetches.json`. No maps, source gameplay definitions, runtime renderer/engine code, server, publishing or upload workflow were changed.

## Original references and physical interpretation

- **RMCSmallChestBlue / Red / Yellow:** `_RMC14/Structures/Storage/Crates/minichestb.rsi`, `minichestc.rsi`, `minichest.rsi`; `base`, one direction. Small plastic body with a separate lid, raised elastic straps, returns and original buckle art. The actual `CrateOpenableSystem.OnInteractUsing` queues the crate for deletion and spawns scrap; it does not hinge a reusable chest. Only the actual base state is bound through the existing single-visible-layer sprite-state contract. Source `noRot` remains respected.
- **RMCCoffeeMachine:** `_RMC14/Structures/Furniture/coffee_machine.rsi`, `coffee_empty_on`, one direction. Physical cabinet, upper grille, separate reservoir, open dispensing bay, tray, vessel and handle. The source prototype explicitly says the machine does not function yet; no brewing, active power, removable contents or invented animation is added. Existing single-layer static binding. Source `noRot` is true; source-supported surface placement has not been invented.
- **RMCCalendarColonist / TWE:** `_RMC14/Structures/Wallmounts/calendar.rsi`, `calendar_colony` and `calendar_twe`, one direction. Thin printed paper with actual thickness, backing, binding and hanging tab. These are the only whole printed source surfaces in this batch, because the depicted object really is thin paper. `RMCCalendarSystem` only supplies date/holiday examine text; it does not change sprite pages. Existing wall-mounted geometry is used, with inferred mounting height and no map-contact verification.
- **RMCPhoneboxOn:** `_RMC14/Structures/Storage/Closets/phonebox_on.rsi`, one direction; actual default `base` + `closed` composition. Physical hollow booth, floor, posts, side panels, stepped roof, separate framed glass door, recessed phone, keypad, handset and cord. `EntityStorageVisuals` drives the two layers. The closed mapping and unmapped `open` study do not claim a single-layer or DoorComponent binding. The door opens about its own hinge only in the explicit art study. `PointLight`, cyan emission, containers, transitions and gameplay remain unsupported. Sprite offset `0.15,0.5` is screen-space, not a world transform.
- **Fireplace:** `Structures/Decoration/fireplace.rsi`, one direction. Separate structural `fireplace` shell only: stone hearth, masonry jambs, real open firebox, resting logs, timber mantel and a hollow chimney. The actual prototype also has visible unshaded `fireplace_fire4` (three 0.1-second frames) and `fireplace_glow` (0.4/0.1-second frames), plus a hidden holiday layer. The model is explicitly incomplete for that live composition: no fire, glow, illumination, heat, sound or festive overlay is claimed. Source layer references are not presented as a complete live source image.
- **CMLinenBin / CMLinenBinFilled:** `_RMC14/Structures/Furniture/linen_bin.rsi`, `linenbin_empty`, `linenbin_full`; unmapped `linenbin_half` study. A true mesh basket with separate rails, rim, real gaps and volumetric folded cloth. Source `SharedCMInventorySystem.OnSlotsFillMapInit` builds 20 slots, inserts the `startingItem` when supplied, then calls `ContentsUpdated`; therefore empty and filled prototype defaults differ even though all three template layers initially exist. `Empty` shows empty; `Low` shows half; `Medium`, `High` and `Full` show full. These are source-backed default reference designs, with no new generic-visualizer binding and no arbitrary contained items modeled. No fill animation is invented.
- **OreBox:** `Structures/Storage/orebox.rsi`, `orebox` + visible `orebox-top` closed default. Five independent front planks, side/back panels, steel reinforcement, actual cavity and removable lid. `SharedStorageSystem.UpdateAppearance` uses `UI.IsUiOpen` to set `StorageVisuals.Open`, which hides `top`. The open shell is an unmapped reference study, not an automatic state link; ore contents and UI remain unsupported.
- **CMFilingCabinetChest:** `_RMC14/Structures/Storage/filing_cabinet.rsi`, `chestdrawer`; unmapped `chestdrawer-open` study. Real two-drawer trays and handles, enclosure and independent top. `BaseBagOpenClose` maps the UI-owned `SharedBagOpenVisuals.BagState` to `openLayer`. The prototype's initially visible open layer is not assumed to be the actual default after initialization. Closed artwork is the reference mapping. The translated upper drawer is a supported physical art study only, not a bound UI/animation state.
- **CMFilingCabinetChestAngled:** same resource, `sidecabinet`, exactly four RSI source slots S/N/E/W. Separate reciprocal directional references retain all slots; one physical chest has explicit alternating front aliases `sourceCardinalFacings: [0,0,3,3]` in S/E/N/W order, with 45-degree offset. The inspected four source drawings show the same drawer front from alternating isometric sides, so blindly rotating the front away for the north frame would be incorrect. Physical side/back dimensions remain inferred. The inherited generic visualizer has no matching `openLayer` in this sprite; no invented opening state. No sprite-state binding is asserted for this alias family.
- **RMCTrashBinBlue:** `_RMC14/Structures/Piping/disposal.rsi`, `trashblue`, one direction. Real separate basket slats, perimeter rails, raised hood with an open mouth, chute and front emblem. Inspected child GenericVisualizer definitions use the exact same `trashblue` image for base/ready/charging/full/engaged/flushing and anchored/loose outcomes. Identical opaque overlaid pixels do not invent a different shape. The structural reference does not simulate disposal, contents, light or UI, and does not use a single-visible-layer adapter.
- **RMCBasketballHoopAlt:** `_RMC14/Structures/basketball_hoop.rsi`, `hoop_alt`, exactly four source directions. Physical base, post, backboard, red target, mounting brace, segmented circular rim and a tapered woven net. All holes are geometry, not a full sprite slab. Four reciprocal source-frame entries use the existing rotating-sprite static contract. Net cross-section, rear fasteners and support depth are inferred. There is no ball interaction or moving net controller in this work.

## Source owners inspected

The actual branch definitions were read, along with inheritance recorded in the source inventory. `Resources/Prototypes/Entities/Objects/base_item.yml` supplies `BaseBagOpenClose`. Source code evidence includes `Content.Shared/Storage/EntitySystems/SharedStorageSystem.cs:UpdateAppearance`, `_RMC14/Inventory/SharedCMInventorySystem.cs:OnSlotsFillMapInit/ContentsUpdated`, `_RMC14/Inventory/CMItemSlotsComponent.cs`, `_RMC14/Crate/CrateOpenableComponent.cs`, `_RMC14/Crate/CrateOpenableSystem.cs`, and `_RMC14/RMCCalendar/RMCCalendarSystem.cs`. Read-only snapshots are retained under `reference/room-props-source/` (storage's snapshot was supplied by the food source audit).

There are eight safe single-layer static entries: three chests, the coffee machine and four hoop directions. They contain no animation clips. Calendar mounting and directional aliases use existing ordinary static fields. Other dynamic-source families are explicitly partial art references; do not treat mapping coverage as complete state coverage.
